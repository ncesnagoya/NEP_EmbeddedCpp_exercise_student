## 2. 復習ポイント（要点だけ）

**ポインタと構造体**
構造体へのポインタ `p` のメンバーには `p->member` でアクセスします（`(*p).member` と同じ）。
関数に構造体を渡すときは、コピーを避け、中身を書き換えるために **ポインタ渡し** を使うのが定石です。本演習の中心となる「ファイルを扱うオブジェクト」も、まずはこの「構造体＋ポインタ渡しの関数」の形で考えると理解しやすくなります。

**動的メモリ**
`malloc(n)` は `n` バイトを確保して先頭アドレスを返し、失敗すると `NULL` を返します。**確保したら必ず `free`** し、`free` 後のポインタは使わないようにします。確保直後の NULL チェックも忘れないでください。この「確保と解放を対にする」という発想は、C++ のコンストラクタ／デストラクタ、そして後半で学ぶ RAII（スマートポインタ）に直結します。

**ファイルI/O**
`fopen(path, mode)` でファイルを開き、`FILE*` を得ます。バイナリ読み書きは `fread` / `fwrite`、位置移動は `fseek`、最後に `fclose` で閉じます。バイナリ操作ではモードに `b` を付けます（`"rb"`, `"wb+"` など）。**開いたら閉じる** という対の関係も、C++ のデストラクタの考え方につながります。

**分割コンパイル**
宣言をヘッダ（`.h`）に、定義を実装ファイル（`.c` / `.cpp`）に分けます。ヘッダの先頭には二重インクルードを防ぐインクルードガード（`#ifndef ... #define ... #endif`）を置きます。本演習でも `binary_file.h` と `binary_file.cpp` に分かれています。

## 3. ミニ演習（手を動かして思い出す）

`prep/problem/byte_store.c` を開いてください。
これは本演習で扱う **binary_file クラスの C言語版** で、構造体 `byte_store` と、それを操作する関数群でできています。
ファイル内の **【予習P-1】〜【予習P-5】** の穴を埋めて、コンパイル・実行できるようにしてください。

```sh
cd prep/problem
cc -Wall -Wextra -o byte_store byte_store.c
./byte_store
```

正しく完成すると、次の出力になります。

```
is open? Y
written size = 256
read size = 256
same
```

埋めるのは、構造体メンバーの定義（P-1）、`fwrite`/`fread` の呼び出し（P-2, P-3）、`malloc`（P-4）、`free`（P-5）の5か所です。
うまくいかないときは、上に示した期待出力と見比べながら、【予習P-1】〜【予習P-5】を順に確認してください。

> このミニ演習で書いた「構造体＋関数」を、当日の step1 では **クラス（コンストラクタ・デストラクタ・メンバー関数）** へ書き換えていきます。
> 「構造体の初期化と後始末を、関数呼び出しの代わりにコンストラクタ／デストラクタへ任せる」という流れを意識しておくと、当日の理解がぐっと楽になります。
